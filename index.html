Project 01

Docusign Web Forms Documentation

Task-centered guidance for customers creating and managing interactive forms.

Product Documentation · Content Modernization · User Experience

As the documentation owner for Docusign Web Forms, I maintain customer-facing content that helps users create, configure, and manage interactive forms for collecting information and completing agreements. The documentation supports customers with varying levels of technical experience, making clarity, navigation, and accessibility essential considerations.

My approach emphasizes organizing information around user tasks rather than product features alone. I focus on clear procedures, consistent terminology, and content structures that help readers locate information and accomplish their goals. Documentation modernization also creates opportunities to examine how existing content can better support evolving product functionality and customer needs.

This work reflects my philosophy that technical documentation is more than a reference resource. When thoughtfully designed and maintained, it becomes an integral part of the product experience and a foundation for customer self-service.

Project 02

Docusign Workspaces Release Notes

Coordinating product updates from stakeholder intake through publication.

Release Communication · Cross-Functional Collaboration · Publishing Operations

Release notes serve as a critical communication channel between product development teams and customers. My work on Docusign Workspaces release notes involves managing the end-to-end communication process to ensure that product updates are accurate, timely, and accessible to their intended audiences.

I work directly with Product and Program managers to coordinate the submission of authoritative release information through a structured Slack intake workflow. My responsibilities include educating stakeholders on the release notes process, managing Jira tickets, coordinating documentation activities, and overseeing the progression of release information from initial submission through publication.

This work requires balancing technical accuracy, editorial consistency, stakeholder coordination, and publishing deadlines. By establishing clear expectations and maintaining a structured workflow, I help create a reliable process for communicating product changes to customers.

The project reflects my broader professional interest in documentation as an operational system that connects product development, technical communication, and customer success.

Project 03

Docusign Release Notes FAQ

Clarifying where customers and partners find release information and notifications.

Content Modernization · Information Architecture · Technical Accuracy · Cross-Functional Review

The Docusign Release Notes FAQ is a customer- and partner-facing resource designed to clarify how release information is communicated, accessed, and maintained. I currently own the editorial revisions for this resource, with a focus on improving the accuracy, organization, and usefulness of the information presented.

The revisions address essential questions about release communications, including how customers and working partners can receive notifications, where they can locate published release notes, how frequently release information is communicated, and what changes to expect in the communication process.

Beyond updating the content, this initiative incorporates a cross-functional review process to ensure technical accuracy and supportability. I work with functional partners to evaluate the information, clarify expectations, and ensure that the guidance reflects processes that the organization can reliably support.

This project demonstrates how technical editing and content governance extend beyond correcting language. By bringing together accurate information, stakeholder validation, and user-centered organization, the revised FAQ is intended to provide a more dependable resource for customers and partners seeking release information.

Project status: Editorial modernization and cross-functional review in progress.

Project 04

Release Notes Assistant: AI-Assisted Documentation Workflows

Exploring AI-assisted release communication with human editorial accountability.

AI-Assisted Writing · Workflow Design · Knowledge Operations

The Release Notes Assistant is an AI-assisted documentation initiative I am developing using Atlassian Rovo. The project explores how AI agents can support the preparation and review of release information while preserving the technical writer's responsibility for accuracy, clarity, and editorial judgment.

My approach treats AI as a component of the documentation workflow rather than a replacement for technical communication expertise. Human oversight remains essential for interpreting product changes, assessing audience needs, resolving ambiguity, and ensuring that published information is useful and trustworthy.

This project connects directly to my doctoral research interests in AI-assisted knowledge production and the transformation of enterprise documentation into infrastructure for customer support. It represents an opportunity to investigate how emerging technologies can reshape documentation practices while retaining professional accountability.

Project status: Ongoing development and workflow refinement.

Professional philosophy

Start with the reader.
Build for trust.

Useful technical communication begins with understanding what someone needs to accomplish. I organize content around those tasks, use consistent language, and make the next step easy to find. Clear structure and accessibility are part of the work from the beginning.

I also see documentation as a shared responsibility. Technical accuracy depends on collaboration with product experts; lasting usefulness depends on review, maintenance, and clear ownership. In AI-assisted workflows, I keep human judgment central to evaluating information and deciding what is ready to publish.

Principles in practice

  • Write for the reader’s task and context.
  • Make information easy to navigate and maintain.
  • Validate guidance with the people responsible for the product.
  • Keep human review and accountability in AI-assisted work.
