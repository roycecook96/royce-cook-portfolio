Project 01

Release Notes Agent: AI-Assisted Release Communication

An AI agent and intake workflow that take release notes from request to review-ready draft.

AI Agents · Atlassian Rovo · Workflow Automation · Human-in-the-Loop Review

Role
Designer and builder
Tools
Atlassian Rovo, Slack Workflow Builder, Jira
Status
In use, fully automated

I built a release notes agent in Atlassian Rovo that triages incoming release note requests and drafts release notes from the information product managers submit. To give the agent reliable input, I paired it with a structured Slack intake workflow that collects the details a release note needs at the moment a request is made.

The workflow keeps people accountable at every step. Technical writers review and edit each AI-generated draft, and product managers approve the final text before it is published. The agent removes the slowest parts of the process (gathering information and producing a first draft) without removing editorial judgment.

Designing the agent meant treating AI as one component of a documentation system: defining the inputs it needs, the output format writers can work with, and the review points where human expertise matters most. The project also grounds my doctoral research on how AI-assisted workflows are changing enterprise documentation.

This confidential project is described at a high level. Internal materials are not publicly accessible. No internal prompts, configurations, source materials, or screenshots are included. The resources below are public technology references, not demonstrations of my agent or evidence of its implementation. Project 02

Roboflow Supervision: Open-Source Tutorial Contribution

Clearer setup guidance for developers building with computer vision models.

Open Source · AI/ML Developer Documentation · Docs-as-Code

Role
Open-source contributor
Tools
Markdown, Python, GitHub pull requests
Status
Merged November 25, 2026

Supervision is Roboflow’s open-source Python library for computer vision. I contributed a documentation update to its Track Objects tutorial, which shows developers how to detect, track, and annotate objects in video.

The tutorial assumed setup knowledge that new readers might not have. I added a Prerequisites section that states the required Python version, gives install commands with minimum package versions, explains that readers need only one of the three inference frameworks the examples cover, and tells readers which examples need a Roboflow API key and how to keep that key out of source control.

I also made the keypoint tracking examples handle video frames where no one is tracked, and I updated the explanation that follows them so the text matches the code.

The contribution went through the project’s pull request workflow, including automated checks and maintainer review, and was merged in November 2026. It reflects how I approach developer documentation: anticipate what readers need before they start, and keep code samples and explanations accurate together.

Project 03

Docusign Workspaces Release Notes

Coordinating product updates from stakeholder intake through publication.

Release Communication · Cross-Functional Collaboration · Publishing Operations

Role
End-to-end release communication
Tools
Slack intake workflow, Jira, Release Notes Agent
Status
Ongoing

Release notes serve as a critical communication channel between product development teams and customers. My work on Docusign Workspaces release notes involves managing the end-to-end communication process to ensure that product updates are accurate, timely, and accessible to their intended audiences.

I work directly with Product and Program managers to coordinate the submission of authoritative release information through a structured Slack intake workflow. My responsibilities include educating stakeholders on the release notes process, managing Jira tickets, coordinating documentation activities, and overseeing the progression of release information from initial submission through publication.

This work requires balancing technical accuracy, editorial consistency, stakeholder coordination, and publishing deadlines. By establishing clear expectations and maintaining a structured workflow, I help create a reliable process for communicating product changes to customers.

This is the process my Release Notes Agent now supports, and running it day to day shows me where automation helps and where human coordination still matters.

Project 04

Docusign Release Notes FAQ

Clarifying where customers and partners find release information and notifications.

Content Modernization · Information Architecture · Technical Accuracy · Cross-Functional Review

Role
Editorial owner
Tools
Cross-functional review
Status
Revisions published November 2026

The Docusign Release Notes FAQ is a customer- and partner-facing resource designed to clarify how release information is communicated, accessed, and maintained. I currently own the editorial revisions for this resource, with a focus on improving the accuracy, organization, and usefulness of the information presented.

The revisions address essential questions about release communications, including how customers and working partners can receive notifications, where they can locate published release notes, how frequently release information is communicated, and what changes to expect in the communication process.

Beyond updating the content, this initiative incorporates a cross-functional review process to ensure technical accuracy and supportability. I work with functional partners to evaluate the information, clarify expectations, and ensure that the guidance reflects processes that the organization can reliably support.

This project demonstrates how technical editing and content governance extend beyond correcting language. By bringing together accurate information, stakeholder validation, and user-centered organization, the revised FAQ is intended to provide a more dependable resource for customers and partners seeking release information.

About

Putting AI to work in documentation.

I design AI-assisted documentation workflows: agents that handle the repetitive parts of documentation work so that writers can spend their time on judgment, accuracy, and the reader. As a Technical Writer 3 at Docusign, I build these workflows into how my team produces customer-facing content.

I built a Rovo agent and a Slack intake workflow that move release notes from a product manager’s request to a review-ready draft. As Scrum Master for the Release Notes Task Force, I connect that automation with the people and processes that keep product information accurate and timely. I also own Web Forms documentation and the Docusign Release Notes FAQ.

How I work

Start with the reader. Build for trust.

Useful technical communication begins with understanding what someone needs to accomplish. I organize content around those tasks, use consistent language, and make the next step easy to find. Clear structure and accessibility are part of the work from the beginning.

Principles in practice

  • Write for the reader’s task and context.
  • Make information easy to navigate and maintain.
  • Validate guidance with the people responsible for the product.
  • Keep human review and accountability in AI-assisted work.

Research

I presented Productizing Knowledge: The Future of Technical Communication in the Age of AI at a technical communication meetup in November 2026. The talk covered how generative AI shifts documentation from static content to dynamic, reusable knowledge systems, with practical examples of AI-assisted documentation workflows.
